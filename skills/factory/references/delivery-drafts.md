# Delivery drafts during QA

Zero attribution: never add or leave co-author, AI, tool, or generator attribution in any output.

Read when QA starts, before shipping a prepared draft, or before consuming a saved reviewer assignment. This is local preparation under an already authorized run. It changes scheduling, never acceptance or publication authority.

## Prepare while QA runs

After the builder commits and required QA readiness gates pass, pin the clean execution checkout, branch, full HEAD and BASE. Browser work still requires **Browser admission**; `no-ui-reach` retains its existing exemption. Dispatch the **QA worker** first. While it runs, the parent prepares the following private artifacts outside all source checkouts, in the existing run-state directory:

- PR title/body and QA handoff skeleton using the installed ship skill's **PR title and body** and shared **QA handoff** sections. Apply the repository template and factory's ordinary `Ref <identifier>` references. Fill observable changes, paths, setup and reproduction from the pinned diff and builder brief. Leave QA, acceptance, remote CI, review results and durable evidence links explicitly pending until inspected evidence exists. A passed local check may be quoted with its original proof identity; never predict a result.
- Neutral reviewer inputs using **Review loop** in [review-and-delivery.md](review-and-delivery.md): tracker/destination, complete criteria source, applicable standards and effective authorization, exact execution checkout/branch/base/head, workspace thread binding, saved reviewer choice, round and review scope. Preserve complete criteria through a private source artifact when needed. Do not inspect for review findings, prewrite a verdict/comment, or include PR prose, builder reasoning, QA verdicts or parent transcripts in these inputs. Resolve the launched worker's actual provenance only at dispatch.
- One bounded receipt containing the unit/group identifiers, canonical repository/common Git directory, checkout, branch, HEAD/tree, resolved target branch and observed remote base SHA, pinned review BASE, complete criteria source identity/content digest, applicable instruction/template versions, saved execution choices, and each artifact's path/digest. Keep the receipt at most 4 KiB; link larger source facts instead of embedding them. Record `prepared`, not a gate result.

Read only the needed ship sections during preparation; do not execute its check, commit, push, PR or comment steps. Keep drafts credential-free and out of git, task services, fixtures, browser sessions and QA-owned evidence paths. Preparation neither takes the browser lease nor changes code, dependencies, runtime or data. It grants no remote draft PR, tracker comment, review dispatch or approval request. QA evidence publication remains the QA worker's existing responsibility.

Use the parent rather than allocate another worker by default. Preserve QA's executor slot and context reserve; if the parent runs QA itself or no independent capacity exists, prepare after QA. Preparation never delays readiness or QA dispatch. If QA finishes first, inspect its result before more drafting; cancel stale preparation after a failure. Missing optional draft text falls back to the ordinary ship/review preparation without blocking a valid gate.

Checkpoint the receipt locator/digest through the existing supported evidence-reference fields and add one **Round log** row with Check `delivery-draft`: unit, full head, preparation start/end times and receipt reference. The round log is not control state; create no second scheduler or database. Partial writes are not `prepared`; save complete artifacts before recording the receipt. On resume, reconcile live workers and checkout first, then validate saved bytes and inputs. Missing or changed artifacts are regenerated locally.

## Release through the existing owners

1. **Revalidate.** Read current checkout/branch/HEAD, clean status, base and target identity, complete criteria source, applicable instructions/templates and saved choices. Compare them and all artifact bytes with the receipt. Changed HEAD, tree, base, criteria, assignment, template or instructions marks affected drafts stale. Do not relabel an old receipt with a new SHA. Apply **After a fix**, scheduling compatibility and criteria-change rules before preparing again; changed acceptance criteria still park the unit. Revalidate at each consumption, including reviewer dispatch after CI.
2. **Publish the PR only through Ship.** Inspect the matching head-bound QA result and its required evidence/publication records. Verify that proof remains valid for the current checkout, runtime, assets, dependencies and data under its existing reuse policy; the same HEAD alone is insufficient after runtime repair. Pending, failed, partial or unreadable required QA blocks draft release. A valid `no-ui-reach` or mechanically proved carried-forward record follows its existing policy. Run **Ship** in [run.md](run.md), retaining every local check, acceptance and authorization gate. Supply validated draft paths and inspected **Check evidence and reuse** proof; complete pending fields from actual results and scrub before publication. Shipping reuses sound text and proof, reruns missing/invalidated checks and owns remote writes/read-back. Remote CI may start from the PR/push; do not wait for PR-triggered CI before creating the PR. An incomplete draft is never published as a passing handoff.
3. **Dispatch review only after CI and QA pass on the current PR head.** Recheck the live PR base/head, required CI policy/results and matching QA record; an unknown signal blocks. Validate neutral inputs again and use them to fill the existing **Review loop** prompt in a fresh read-only reviewer session, preserving independent child-lane isolation. No cached findings or result accompanies it. Actual review comments and provenance come from that reviewer. Merge, risk, staging and cleanup gates stay in their existing owners.

Inspect existing PR/comment/thread receipts before retrying remote actions after interruption; reuse identical published content only after supported read-back. A local receipt never proves publication, review completion, terminal writer state or permission. Persist confirmed PR/comment/run IDs through existing checkpoint fields, preserving original counters and choices.

## Verify the overlap

Record QA start/end, draft preparation start/end, PR publication and review dispatch times in the existing round log/evidence. Claim overlap only when measured intervals intersect; fallback stays serial. The possible saving is the smaller of QA duration and draft preparation duration, minus coordination overhead; do not claim a measured full-run speedup from that bound.

Verify a same-head pass consumes prepared text through Ship; failed/pending QA releases nothing; changed HEAD or artifact bytes regenerate drafts; moved base reruns compatibility and affected gates; changed criteria park; and missing/failed CI prevents review while allowing only the already-gated PR creation. Confirm serial fallback and resumed partial publication preserve ownership and do not duplicate remote writes.
