# Execution and continuity

Zero attribution: never add co-author, AI, or tool attribution in any output.

Load at run start and before recovering a worker. The parent owns advancement through the factory stages; a worker's last message cannot end the run while authorized, unblocked stages remain.

## Select once

Honor explicit user backend/provider/model requirements. An unavailable required choice parks affected units with its reason. Otherwise prefer T3 when its live capability query succeeds and usable providers support the required launch mode. Exposed tool names alone do not prove connectivity. A failed capability query is one failure, not a reason to repeat slow calls; use native local execution when workspace policy permits delegation and the runtime exposes it. Report the fallback and cause. This is another executor, not a T3 authentication workaround. Never reuse OAuth secrets, change sign-in mode, or control T3 through shell commands.

Inherit the builder harness, provider and model from the session the user started, unless the user explicitly overrides them. Resolve this identity from live session metadata; missing identity is a setup blocker, never a reason to ask which agent builds or silently use a project default. Recovery and fresh-parent handoffs retain the original builder rather than inheriting the replacement parent.

Ask only the unanswered reviewer choice in **Start** ([`run.md`](run.md)), once. T3 options require live cross-provider launch support when different from the builder; native options come from the available local executor. Recommend a different provider and name each option's live catalog default. Read **Capabilities** in `orchestrate-t3/references/t3-tools.md` for T3 catalog interpretation. Do not select a reviewer when the user is away. Persist backend and builder/reviewer harness/provider/model choices in the checkpoint and round log. Reuse explicit or saved choices on resume. An unavailable required choice parks affected units; do not substitute or reopen intake silently.

Native workers run the chosen provider/model. Reviewers follow **Independent review** below. Report same-provider review accurately. A workspace that requires different-provider review retains that gate. A missing local executor parks; do not invent tools or remote workers.

## Dispatch

Discover the workspace's supervisor adapter before dispatch or provider/parent handoff when one is provided. Read its supported schema/help and use its budget, checkpoint and completion reconciliation operations; no remembered MCP/tool/CLI names. Persist the verified checkout/head, worker IDs/states, budgets, ownership and next gates before waiting. Reconcile durable completion records with live workers and checkout state before any fresh parent or replacement worker launch. A supervisor record does not prove a gate or authorize a duplicate writer; unavailable live state retains the existing unknown-writer stop. Without an adapter, use the supported harness and round-log continuity contract below; do not claim automatic host restart.

When MCP omits usage or the context window, try the adapter's documented read-only local telemetry source before parking. Resolve the current root run and its native thread binding; a T3 thread ID, child usage, or cumulative billing total cannot substitute for native root occupancy. Preserve the sample's observation time. Missing, incompatible or stale telemetry remains a blocker; historical logs cannot become fresh evidence. Use the adapter's supported paths on macOS, Linux and WSL2, including custom profiles, without adding platform-specific scripts when an existing reader suffices.

For a prepared product checkout, launch through live `t3_thread_launch` with its owning `projectId` and explicit `workspaceStrategy` of type `existing_worktree`, or another supported launcher that binds that exact checkout. Never use `delegate_task` with `isolation: "shared"` when only the prompt names a different checkout. For T3 launches, prepend a no-write readiness acknowledgement to the assignment and require the worker to wait for the parent's release. Compare returned/live thread project, worktree path and branch against its verified assignment, then release only a matching ready worker through the supported send control. Save its implementation run ID from the receipt/live read before checkpointing for completion; the readiness turn cannot satisfy an implementation gate. A mismatch blocks writes; repair the launch contract within recovery caps after confirming the wrong writer is terminal.

Checkpoint the supervisor's actual project, checkout, branch and head separately from every worker's project/checkout assignment. A parent running at the workspace root does not become a product-worktree parent because its child implements there. A root-bound T3 parent may report `worktreePath: null`; reconcile it against its registered project root rather than assigning the product worktree. With the workspace supervisor adapter, use `parent_binding` for the actual parent and each worker's `project_id` for its owning project; unit defaults do not replace parent identity. Preserve this distinction for replacement-parent launches.

Run fresh supervisor preflight before **each** dispatch and completion import, including automatic delivery when the host exposes that hook. Do not reuse an earlier allowance. Preserve helper exit status through wrappers: nonzero means no downstream import, launch or gate advancement. Save bounded diagnostics, stable error codes and result paths; a successful log reader cannot clear the helper failure. Reconcile and persist completion before delivering it. Without a supported pre-delivery host hook, report that automatic host delivery remains unguarded.

Keep the existing checkout policy, assignment ownership, capacity limits, stage skills, and current effective access authorization. Native builders receive the same applicable instructions and filled `orchestrate-t3/references/worker-prompt.md` contract as T3 builders, and implement through `tdd-loop`; loading that prompt does not invoke T3. Native reviewers use the read-only prompt in **Review loop** ([`review-and-delivery.md`](review-and-delivery.md)). Save the worker ID, checkout/branch/head, ownership, stage and remaining attempt budgets in **Round log** before waiting. Use `execution` as its Check value; its Tried cell records `worker`, `checkout`, `branch`, `head`, `owned-files`, `stage`, `worker-recoveries-used`, `runtime-repairs-used`, `qa-rechecks-used`, `ci-attempts-used`, and `review-rounds-used`. Native executor tools come from the live runtime; unavailable capacity queues work without dispatching another writer into its checkout. Apply **Dependency-aware scheduling** in `run.md` before dispatch: record prerequisite state, runtime/data isolation and any browser lease owner; parent integration remains serial.

## Independent review

Launch every review round in a fresh session with conversation inheritance disabled through the live launch schema (`fork_turns: "none"` when exposed). Provider/model inheritance is separate from conversation inheritance; a different provider alone does not establish independence. Confirm the launch used a fresh session and no conversation fork. If the backend cannot provide that isolation, use an authorized supported local launcher; otherwise leave the review gate incomplete and report why.

Supply only the issue criteria and their source, applicable instruction/standard paths and effective authorization, verified checkout/branch, pinned base/head, review scope and reporting destination. On later rounds add only previous findings and the builder's replies needed to assess them. Keep builder reasoning, implementation narrative, prior success verdicts and parent transcripts out of the assignment. Evidence paths may be inspected on demand; the reviewer forms its own findings from requirements, code and checks.

Any Standards/Spec child lanes use the same fresh-session boundary and receive only their axis's inputs. They do not inherit the supervisor's conversation or each other's conclusions.

Return at most 400 words to the parent: tested base/head, findings by axis/severity, checks run and not run, blockers, and the complete report path or posted comment ID. Keep every finding and supporting detail in that report/comment; the concise return never drops findings or substitutes for reading the complete gate record. Raw logs and transcripts stay out of the return.

## QA worker

Run QA browser work and evidence publication in a QA worker when the executor supports one. It loads `agentic-qa` and then [`evidence-publication.md`](evidence-publication.md) on the unit's verified head checkout and ready stack URL, under the unit's browser lease and the run's authorization; it edits no code. It returns a bounded summary: result, cell counts (pass, fail, gap, not reachable), finding IDs with one line each, local evidence paths, uploaded attachment IDs, the posted comment ID and the `Checks:` lines it ran. Without worker support the parent runs both itself under the same limits, checking images by metadata only.

The parent never reads image bytes or saved oversized tool output into its context. It checks images by metadata (dimensions, byte size, hash) from a local tool, and queries a large saved result for the fields it needs (for example with `grep` or a JSON query) instead of reading the file. Gate decisions still read the posted record back, in bounded sections.

## Supervise and recover

Before a large fan-out, review return or provider handoff, apply the available supervisor budget check and preserve at least 25% of the receiving context budget for tool envelopes, pending results and the next decision. Parent usage, pending payloads and child inheritance all count; a child's unused budget does not enlarge the parent's. Request bounded summaries and log/report paths rather than full parallel transcripts. Keep complete findings durably accessible and read the gate record in bounded sections.

Set the return contract to fit the adapter's allowance, including encoded metadata, transport overhead and every outstanding return. A report at the full history cap leaves no space for its envelope. If the total cannot fit, serialize dispatch or lower the actual return contract while retaining complete evidence by reference; never lower only its estimate or raise the cap to force a pass. Repeat the check with fresh telemetry at completion import.

Compact the parent through supported harness controls before a provider handoff when that reserve would be lost. Discover live support; do not invent a compact MCP operation or claim a tool ran when none exists. If supported compaction is unavailable, save checkout/head, worker IDs/states, budgets and outstanding gates, confirm active writer state, then use an authorized fresh parent thread with a neutral durable handoff or reduce the payload through supported controls. Reconcile live state before resuming; no duplicate writer or skipped gate. Independent reviewers retain their fresh-session contract above.

Wait or poll in intervals of at most 60 seconds; report actual progress at least every 60 seconds. Record time of last observed message/tool/check progress. After three minutes without progress, inspect worker state, pending requests, and active commands. A running test/build or a healthy queued worker is still active; elapsed time alone does not authorize cancellation or replacement.

An operational question covered by current authorization is answered from the assignment and policy. Use a pending-question response when supported. A permission prompt that the API cannot approve remains an access gate; stop or interrupt only through supported tools and confirm terminal status before any reassignment. Never fabricate an approval.

`completed` or `idle` means a turn ended. Read the full report and verify checkout, head, dirty files, exit status and gate evidence. Missing required output or a recoverable worker failure resumes the missing stage on the same checkout. Diagnose first: fix instructions for a mistaken approval, change an unavailable executor/provider, or reduce a failed oversized request. Keep all acceptance checks and stage budgets.

Allow at most two worker recovery attempts per unit per run, separate from runtime repair and QA/CI/review caps. Normal builder follow-ups for QA/review findings and requested evidence do not consume worker-failure recovery attempts; their own stage caps remain binding. Every recovery attempt needs a diagnosed changed condition; repeated identical failures park. Confirm the previous writer ended or was stopped before resuming; inspect and preserve its partial work. A lost launch response is reconciled against live worker listings before another launch. If the old executor is unreachable and writer status cannot be confirmed, park that checkout rather than launching a competing writer. Completed stage evidence remains reusable only under its original revision/environment identity.

This factory-only recovery replaces `orchestrate-t3`'s standalone post-commit relaunch refusal: resume missing work after confirmed stop, including when a commit exists; never redo completed implementation. No other stage refusal is overridden. Reuse passing check logs only after inspecting the shared ship policy’s **Check evidence and reuse** record and verifying every identity; a worker’s success summary alone does not count. Failed coverage and synthetic substitutes cannot save a rerun of the real gate.

## End and resume

Continue until every unit is merged with required handover, reaches its authorized ceiling, or has an evidenced terminal blocker. A stage skill returning to the parent is not a final factory result. High-risk human review, denied access, essential missing facts, scope conflicts, unreadable gates and exhausted caps remain legitimate stops.

Attempt diagnosed, authorized recovery within the existing caps before parking. An explicit user pause or stop ends automatic advancement immediately; preserve its intent through interruption recovery.

Before ending, save each unfinished unit's standard session handoff in the checkpoint and **Round log**, then emit it in the run report. Use the workspace supervisor's supported handoff operation when present; otherwise follow [`session-handoff.md`](session-handoff.md). The handoff contains current state, required setup and a copyable next prompt, with saved execution choices, worker ownership and budgets. Refresh it after each gate so a host can render it from the last checkpoint after forced interruption. Missing or stale live state is marked unknown; no interrupted agent response is assumed. If all its workers are confirmed stopped, stop task-owned parked services with their recorded safe command, preserving code, volumes and unpublished evidence; retain the verified restart command. Unknown writer state or a failed stop preserves the stack and reports the reason. Never perform merged-only deletion for a parked unit.

After interruption or a new authorized run, read tracker/PR signals, worker listings and checkout identity before acting; resume the first missing gate. Logs locate work but cannot prove a gate. Attempt budgets carry across an interrupted run; a newly user-started run uses its documented caps. These instructions operate while the parent is running. They do not create a background supervisor or automatically restart a terminated host session.
