# Supervisor receipts

Zero attribution: never add or leave co-author, AI, tool, or generator attribution in any output.

Read when resuming supervision, entering another phase or considering a repeated history/comment/catalog read. Start with the workspace adapter's compact receipt when available. It is a navigation view of existing checkpoint, worker/run identities, counters, selected agents, next gate and evidence pointers. It grants no authority, never passes acceptance and never replaces fresh dispatch/completion preflight or live writer reconciliation. Without this adapter, keep the same bounded facts in the existing checkpoint/round log; do not invent an installed command or another state store.

## Save once, expand when needed

After discovery or a completed phase, retain a bounded private source receipt through the existing checkpoint's supported source/evidence fields. Store the source locator, exact revision/version, observation time, coverage/cursor and content digest. The private artifact contains the necessary facts and original record references, not full parallel histories or capability catalogs. Keep all findings in the complete result/gate record. Save only source kinds supported by the adapter; its current schema owns concrete field names and limits.

At the next phase, read the compact view and request only missing or changed source records. Reuse discovery only after local bytes and scope match, source discovery was complete, and a fresh supported metadata check establishes the same version. A cached timestamp cannot become a new observation. A missing version signal, unreadable probe, changed file, moved execution head, changed assignment or incomplete page requires the affected discovery again. Page the compact view to completion or state which workers/sources remain unseen; a partial page cannot justify a full-run decision. Oversize output requires smaller pages, never silent truncation.

| Source | Retain | Recheck before reuse |
| --- | --- | --- |
| Capabilities | Selected harness/provider/model, required launch/review controls and catalog observation reference. Preserve the user's choices. | Same connected host/provider generation and choices. Reconnect, changed availability/model or unsupported control invalidates discovery. No cheap reliable version signal means query the supported capability source again. |
| Tracker records | Unit/head, exact criteria source, relevant comment IDs, original creation/update identities, newest relevant record, completeness and supported cursor. | Detect new, edited and deleted relevant records, including edits before a saved cursor. An issue's timestamp alone is not proof that its comments are unchanged. Missing authoritative delta/version coverage requires bounded rediscovery through all necessary pages. A newer blocked/partial record cannot be hidden by an older pass. |
| Worker progress | Original task/thread/run IDs, last inspected event position, bounded result locator/digest and outstanding ownership. | Fresh lightweight live state and the original run identity. Fetch only unseen events or the required result when the host supports it. A receipt never proves a writer terminal or acknowledges automatic delivery. |

## Advance with evidence

Inspect the full matching gate record once in bounded sections before making that gate's decision; do not infer success from a source summary, local digest match, saved next-gate name or successful worker exit. Retain its exact version and measured proof references with the checkpoint. Reuse an already inspected record only when current metadata, execution/runtime/data/dependency identity and the gate's existing reuse policy permit it. Refresh affected proof after changes. Current-head CI, independent review, QA, merge and deploy checks keep their existing requirements.

On parent replacement, read the compact receipt first, preserve choices/counters/ownership, then reconcile live workers and checkout before any dispatch. Reload only policy sections or source records invalidated or missing from the new context. Never replay the entire thread to reconstruct facts already retained. A saved source version must come from an actual supported observation, not a guessed timestamp, local clock refresh or another lane's result. Missing host support remains an explicit capability limit; receipts do not implement host restart, compaction ordering or automatic delivery hooks.
